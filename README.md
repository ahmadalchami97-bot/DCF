# Investment-Grade Company Analysis Engine

A modular Python engine that turns raw financial-statement inputs into a
complete, **fully-formula-driven, auditable Excel workbook** — historical
analysis, driver-based forecast, a transparent DCF, scenarios, sensitivities,
diagnostics, a dashboard and a written investment conclusion.

The deliverable an analyst actually uses is the **`.xlsx` workbook**. The Python
package *generates* it. Crucially, the workbook contains **live Excel formulas**,
not values baked in by Python — so every output traces back to an input, the
model recalculates when you change a cell, and it is auditable end to end.

```
pip install -r requirements.txt
python build_model.py                       # -> examples/sample_company.xlsx (worked example)
python build_model.py --blank -o my.xlsx     # blank template, ready for your data
python build_model.py --json data.json -o out.xlsx
```

Open the result in Excel or LibreOffice and start on the **Cover** sheet.

---

## 1. Why it is built this way

The brief asks for highlighted input cells, formula cells, colour coding, named
sections, auditable formulas — *and* modular, defensively-programmed code. The
design satisfies both:

* **A spreadsheet is the product.** Analysts live in Excel; they paste data and
  expect everything to recalculate. So the engine emits real formulas
  (`=Forecast!$C$11/(1+WACC)^1`, `=IF(AND(ISNUMBER(...)),...)`) into styled cells.
* **Python is the factory.** All logic — layout, formula construction, the
  assumption engine, styling — is modular, testable Python. One place to read,
  one place to change.
* **It is verified, not hoped.** A dependency-free Excel-formula evaluator
  (`tests/xlcalc.py`) recomputes every formula in the generated file and
  cross-checks the results against an independent roll-forward of the sample
  data. 1,000+ live formulas are evaluated on every test run — zero errors, zero
  circular references.

### Non-negotiables, and how they are met

| Requirement | How |
|---|---|
| Don't invent / guess data | Missing cells stay blank; formulas degrade to `n/a` / `n/m`; the Checks sheet flags gaps. Sample data is generated by a balancing roll-forward, never hand-faked. |
| Everything traceable to a formula/input | Every output is a live formula referencing registered input cells. No pasted values. |
| No hardcoded assumptions where a driver exists | Growth, margins, capex, D&A, working capital are derived from the company's own history; scenarios are explicit tilts. |
| Show complex calcs step by step | WACC, the FCFF build and the DCF are laid out line by line, never compressed into one opaque cell. |
| Industry-agnostic | A "Generic" business type always works; turnover/working-capital metrics self-disable when not meaningful; the forecast falls back to trend + mean-reversion when no drivers are supplied. |
| Beautiful & usable | Consistent palette, section bands, a legend, frozen headers, dynamic colour-coded labels, a one-page dashboard. |
| Plain-English interpretation everywhere | Improving / Stable / Deteriorating, Strong / Weak, Undervalued / Overvalued, etc., generated by explicit, centralised threshold rules. |
| Defensive against errors | `IFERROR`, `ISNUMBER`, zero/negative-base guards on every ratio; terminal growth clamped below WACC; a whole diagnostics sheet. |

## 2. Architecture

```
build_model.py            CLI entry point (sample / blank / from JSON)
dcf/
  config.py               palette, number formats, interpretation thresholds, default assumptions
  styles.py               openpyxl style objects + one apply() used by every sheet
  utils.py                cross-sheet cell registry + defensive Excel-formula builders
  schema.py               the input contract (every line item, input vs subtotal)
  sample_data.py          worked example, built by a balancing roll-forward
  workbook.py             orchestrator: creates sheets, builds in dependency order, polishes
  sheets/
    common.py             build Context + shared drawing helpers (bands, headers, legend, label colouring)
    cover.py  inputs.py  historical.py  assumptions.py  wacc.py  forecast.py
    dcf.py  sensitivity.py  scenario.py  checks.py  dashboard.py  conclusion.py
tests/
  xlcalc.py               dependency-free Excel-formula evaluator (verification engine)
  test_model.py           the test suite (11 tests)
  recalc.py               optional LibreOffice-UNO recalculation helper
examples/
  sample_company.xlsx     the worked example (regenerable)
  blank_template.xlsx     empty data-entry template
docs/METHODOLOGY.md       formula-level documentation of every calculation
```

**The cross-sheet registry (`utils.Refs`)** is the backbone. As a sheet writes a
cell it registers it under a stable key (`in.revenue@4`, `wacc.value`,
`fc.fcff@3`). Other sheets reference it by key, and the registry resolves to an
absolute, sheet-qualified address. Sheets are therefore **built in dependency
order** (Inputs → Historical → WACC → Assumptions → Forecast → DCF →
Sensitivity → Scenario → Checks → Dashboard → Conclusion → Cover) even though
they are displayed in reading order.

**Layered design:** Inputs (data) → Historical / WACC / Assumptions / Forecast
(calculation) → DCF / Sensitivity / Scenario (valuation) → Checks (diagnostics)
→ Dashboard / Conclusion (output). Inputs are yellow; on-sheet formulas are
black; cross-sheet links are green; key outputs are shaded; headline results are
boxed. The legend (Cover & Inputs) explains the coding.

## 3. The twelve sheets

| Sheet | What it does |
|---|---|
| **Cover** | Title, headline valuation, clickable contents, legend, quick-start. |
| **Inputs** | The only place you type. Income statement, balance sheet, cash flow, shares, optional volume/price drivers, and market/WACC references. Subtotals (gross profit, EBIT, EBITDA, totals, CFO/CFI/CFF) are computed here as formulas. |
| **Historical** | ~45 metrics across growth, margins, returns (ROE/ROA/ROIC/ROCE), liquidity, leverage, efficiency (DSO/DIO/DPO/CCC, turnovers), cash flow and shareholder returns — each with a plain-English read. |
| **Assumptions** | The DCF assumption engine: derives base-case drivers from history, builds Base/Bull/Bear/Downside via explicit tilts, exposes a **scenario selector**, and tags every assumption *model-derived / assumption / fallback*. |
| **WACC** | CAPM cost of equity, after-tax cost of debt, market-value weights → WACC, built one line at a time, with fallback handling for missing market data. |
| **Forecast** | Revenue growth fades to the terminal rate; margins fade to target; capex/D&A/working capital scale with revenue → unlevered free cash flow, every step shown. |
| **DCF** | Discounts FCFF at WACC, terminal value by perpetuity (with an exit-multiple cross-check), EV → equity bridge → implied value per share, plus TV-share and implied-multiple cross-checks. |
| **Sensitivity** | Three live heat-maps: WACC × terminal growth, WACC × exit multiple, start growth × terminal margin. |
| **Scenario** | Four full DCF runs side by side; the Base column reproduces the headline to the cent. |
| **Checks** | 16 automated diagnostics with PASS / REVIEW / FAIL and an overall data-health verdict. |
| **Dashboard** | One-page tearsheet: snapshot, headline valuation, KPIs, returns, DCF bridge, scenario range, risk flags and a formula-driven investment view. |
| **Conclusion** | A written, mostly formula-driven thesis: stance, value drivers, risks, swing assumptions, upside/downside and caveats. |

## 4. Input → output map

| You enter (Inputs) | Flows into | Headline output |
|---|---|---|
| Income statement lines | Historical margins/growth; Forecast EBIT margin anchor | Margins, EBIT, EBITDA paths |
| Balance sheet lines | Liquidity/leverage ratios; net debt; working-capital intensity | Net-debt bridge, leverage reads |
| Cash flow lines | CFO/FCF history; capex & D&A intensities | Forecast FCFF |
| Shares + price | Market cap → WACC weights; per-share bridge | Value per share, upside |
| Beta / Rf / ERP / Kd / tax | WACC build-up | WACC → discount factor |
| Scenario selector (1–4) | CHOOSE() across the assumption table | Whole forecast & DCF reprice |

Change any yellow cell and every linked figure — through to the Dashboard and
Conclusion — updates automatically.

## 5. Major assumptions and where they live

All on the **Assumptions** sheet, each tagged with its source:

| Assumption | Base-case derivation | Scenario behaviour |
|---|---|---|
| Year-1 revenue growth | Blend of historical revenue CAGR and latest-year growth, clamped to a sane band | ±3pp (Bull/Bear), −6pp (Downside) |
| Terminal growth `g` | Conservative long-run default (2.5%), **clamped below WACC − 1%** | ±0.5pp, −1.0pp |
| Terminal EBIT margin | Trailing 3-year average EBIT margin | ±2pp, −5pp |
| D&A / capex / working-capital % | Historical-average intensities (fallback defaults if no history) | scenario-invariant |
| Tax rate | From the WACC sheet (market input or fallback) | scenario-invariant |
| Exit EBITDA multiple | Generic default (8×) — cross-check only | scenario-invariant |
| WACC components (Rf, ERP, β, Kd, t) | **WACC** sheet, from market inputs with labelled fallbacks | — |

Defaults and thresholds live in `dcf/config.py` (`Defaults`, `Thresholds`) — a
single auditable place for every tunable number and labelling rule.

## 6. Usage guide

1. **Start from the template:** `python build_model.py --blank -o my_company.xlsx`.
2. **Fill the yellow Inputs cells.** Minimum: revenue and equity. The more you
   supply (full statements, market data), the deeper the analysis. Leave unknown
   cells blank — the model marks them missing and continues.
3. **Mind the conventions** (stated on the Inputs sheet): COGS/SG&A as reported
   (they include their D&A); enter capex, dividends and buybacks as positive
   amounts; D&A is entered once, in the cash-flow block.
4. **Review Assumptions.** The base case is pre-derived from your history; adjust
   any cell if you have a different view. Set the scenario selector (1–4).
5. **Read the Dashboard and Conclusion;** stress the call on Sensitivity and
   Scenario; check the **Checks** sheet for any flags.

To regenerate the worked example: `python build_model.py`.

## 7. Verification

`tests/xlcalc.py` is a small, faithful Excel-formula evaluator. It loads the
generated workbook, evaluates every formula (resolving cross-sheet references,
with cycle detection) and applies Excel value semantics (blank = 0 in
arithmetic, text → `#VALUE!`, `IFERROR` catches errors, etc.). The test suite
then asserts:

* no formula errors and no circular references anywhere (sample, blank, partial);
* Inputs subtotals reproduce the independent roll-forward exactly;
* the balance sheet balances every year;
* WACC equals its CAPM build-up; the DCF outputs are positive and sane;
* the Scenario "Base" column and the Sensitivity centre cell both equal the
  headline value per share;
* the scenario selector re-prices the whole model;
* the blank template produces no errors and the diagnostics flag the gaps.

```
python tests/test_model.py      # 11/11 passing
# or, if pytest is installed:
pytest -q
```

(`tests/recalc.py` can drive a real LibreOffice recalculation via UNO where the
environment supports it; the bundled evaluator is the primary, dependency-free
check.)

## 8. Limitations & missing-data dependencies

* **Garbage in, garbage out.** A DCF is only as good as its inputs; replace the
  fallback market data and review the derived assumptions for your own view.
* **Fallbacks are labelled, not hidden.** With no market data the WACC uses
  default Rf/ERP/β and book equity for weights; with no history the intensity
  drivers use conservative defaults. The Assumptions/WACC sheets say so, and the
  per-share value needs current shares (and a price, for the upside read).
* **Terminal value usually dominates.** Treat WACC and terminal growth as the key
  swing factors — that is what the Sensitivity sheet is for.
* **Bank/insurer specifics are light.** The framework is industry-agnostic and
  robust, but financials-sector drivers (NIM, loss ratios, capital) are noted
  rather than fully modelled; use the generic engine and sector judgement.
* **Two-way growth×margin sensitivity** uses a clearly-labelled simplified
  constant-growth model (the other two tables are exact), because the cash flows
  themselves move with those levers.
* **Not investment advice** — an analytical tool to support judgement.
